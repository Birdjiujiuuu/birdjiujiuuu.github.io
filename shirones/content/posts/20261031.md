在搭建个人博客和图床时，为了兼顾免费与稳定，我们通常会选择 GitHub Pages 或 Cloudflare Pages 作为源站托管服务。然而，由于跨境网络路由的波动，国内用户访问这些海外节点的速度往往很一般。

为了解决这个问题，我们可以使用 **边缘安全加速** ，以此来提高国内用户的访问速度。

## 架构说明

为了便于说明，本文使用以下域名代称，加速服务使用 阿里云 ESA 免费版：

| 角色 | 域名 / 地址 |
| :--- | :--- |
| 根域名 | `example.com` |
| 主站地址 | `www.example.com`（源站：GitHub Pages `username.github.io`） |
| 图床地址 | `imgs.example.com`（源站：Cloudflare Pages `project.pages.dev`） |

## 前置准备

无论是加速博客主站，还是加速图床，下面几步都是共通的，这是接入 ESA 的基础。

### 添加站点与验证

1. 在阿里云 ESA 控制台添加站点 `example.com`，选择 **CNAME 接入**。

::: important 关于获得加速与保护的区域
- 全球（不包含中国内地）：适合未备案的域名，但是实际加速效果有限。
- 全球：适合备案的域名，加速效果显著。
:::

2. 添加完成后，系统要求验证域名所有权。在域名托管平台的 `Advanced DNS` 添加一条 `TXT Record`，主机记录为 `_esaauth`，值填 ESA 提供的字符串。

::: note 注意
`_esaauth` 验证成功后**请务必保留**，这是后续证书自动续期的凭证。
:::

### 添加 DNS 记录（ESA 侧）

在阿里云 ESA 控制台的站点管理中，进入 **DNS** → **记录** 页面：

1. 添加一条指向博客源站的记录：主机记录填 `www`，记录类型选 `CNAME`，记录值填 `username.github.io`，并**开启代理加速**。
2. 如果需要图床，再添加一条：主机记录填 `imgs`，记录类型选 `CNAME`，记录值填 `project.pages.dev`，同样**开启代理加速**。

### 修改 DNS 解析（域名托管平台侧）

在域名托管平台的后台，清理掉原来指向 GitHub IP 的所有 `@` 记录，以及指向 `github.io` 和 `pages.dev` 的旧 CNAME 记录，然后全部替换为 ESA 分配给你的专属 CNAME 地址：

| Host | Value | TTL |
| :--- | :--- | :--- |
| 根域名 `@` 或需要加速的子域名（如 `www` 或 `imgs`） | 阿里云给你提供的对应域名加速地址 | 自动 (Automatic) |

### 申请 SSL 证书

1. 在 ESA 控制台选择 **站点管理** ，左侧导航栏选择 **SSL/TLS** → **边缘证书**，页面下方可以看到 **托管 DCV** 区域。
2. 在 **托管 DCV** 区域，复制系统为你生成的 CNAME 信息（免费证书对应的是 `_acme-challenge` 开头的记录），并在域名托管平台添加对应的 CNAME 记录：

| Host | Value | TTL |
| :--- | :--- | :--- |
| `_acme-challenge`（非泛域名则填 `_acme-challenge.<子域名>`，如 `_acme-challenge.www`） | 控制台复制的完整 CNAME 目标地址（`<hostname>`为你的域名） | 自动 (Automatic) |

::: note 注意
该 CNAME 记录**请务必保留**，这是后续证书自动续期的凭证。
:::

3. 完成 DCV 配置并等待 DNS 生效后，在 **证书管理** 板块，点击 **申请免费证书**：

- **证书颁发机构**：选择 `Let's Encrypt`
- **证书域名**：填入你需要用到的**单域名**，例如：`example.com, www.example.com, imgs.example.com`

> *提交后，由于 DCV 记录已经提前配好，系统会自动完成验证，证书通常几分钟内即可签发。*

4. 证书签发完成后，开启下方的 **强制 HTTPS**。

## 主站加速配置（GitHub Pages）

证书签发后，访问主站大概率会遇到 `ERR_TOO_MANY_REDIRECTS`（重定向次数过多）。

::: tip 为什么会死循环？
GitHub Pages 默认开启了强制 HTTPS。如果 ESA 用 HTTP 协议回源，GitHub 会返回 301 跳转回 HTTPS；ESA 如果没处理好这个跳转，浏览器就会在 HTTP 和 HTTPS 之间无限循环。
:::

### 配置主站回源规则

进入 ESA 控制台 → **规则** → **回源规则**，为主站新建一条规则：

| 参数 | 填写内容 |
| :--- | :--- |
| **匹配条件** | 主机名等于 `www.example.com`（或 `example.com`） |
| **回源协议** | **HTTPS**，端口 **443** |
| **回源 Host** | **`www.example.com`** |
| **回源 SNI** | **`www.example.com`** |

配置保存后，重新访问主站，重定向问题就会消失。

## 图床加速配置（Cloudflare Pages）

此时，访问 `imgs.example.com` 可能会无法访问或直接返回 `403 Forbidden`，然而直接访问 `project.pages.dev` 一切正常。

::: tip 为什么会 403？
Cloudflare Pages 对回源请求的校验极其严格。Cloudflare 依赖请求头里的 `Host` 和 TLS 握手里的 `SNI`（服务器名称指示）来识别你要访问哪个站。如果 ESA 发过去的身份对不上，就会被直接拒绝服务。
:::

### 配置图床回源规则

为了避免与主站冲突，需要在 ESA 中**单独为图床新建一条回源规则**，并确保其**优先级高于主站规则**：

| 参数 | 填写内容 |
| :--- | :--- |
| **匹配条件** | 主机名等于 `imgs.example.com` |
| **回源协议** | **HTTPS**，端口 **443** |
| **回源 Host** | **`imgs.example.com`** |
| **回源 SNI** | **`imgs.example.com`** |

添加完回源规则后，你的自定义域名应该能够正常访问图床了。
